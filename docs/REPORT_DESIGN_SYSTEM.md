# Power BI Health Assessment – Report Design System V1

## Purpose
Create an assessment that looks like a boutique BI consultancy deliverable rather than a generic freelancer report.

## Visual Tokens
| Token | Value | Use |
|---|---|---|
| Deep Navy | #0B1F33 | Headlines, executive blocks, high-authority surfaces |
| Interaction Blue | #2F6BFF | Navigation cues, neutral emphasis, process steps |
| Success | #1E9E63 | Verified improvement, healthy score, completed remediation |
| Warning | #E39A22 | Medium risk, before-state score, P2 |
| Critical | #D64545 | P1 / critical findings only |
| Background | #F5F7FA | Report canvas |
| Text | #1E2A36 | Main copy |
| Muted | #66788A | Secondary metadata |

## Design Rules
1. Use risk colors semantically, never decoratively.
2. Executive message first; technical evidence second.
3. Every issue must answer: what, why it matters, priority, effort.
4. Keep the Standard report at 8–12 pages.
5. Premium may extend to 12–18 pages with a deeper implementation blueprint.
6. Use fixed section architecture so report generation can be automated.
7. Keep current design brand-neutral until the final company name is chosen.

## Core Visual Components
- 0–100 Health Score ring
- category score bars
- P1/P2/P3/P4 pills
- finding cards
- Before/After verification block
- business impact vs implementation effort matrix
- action-plan timeline
- code Before/After blocks
- executive KPI cards

## Standard Report Architecture
1. Cover
2. Executive Summary
3. Health Overview
4. Priority Findings
5. Data Model & Relationships
6. DAX Quality
7. Power Query / Performance
8. Dashboard UX / Business Alignment
9. Quick Wins
10. Priority Matrix
11. Before/After or Validation Evidence (when available)
12. Recommended Next Steps

## Commercial Purpose
The report must make three things obvious:
1. The assessment is systematic and repeatable.
2. Findings are prioritized rather than dumped as a checklist.
3. The natural next paid step is implementation support or Re-Validation.
